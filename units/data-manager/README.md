# DATA MANAGER

Data Manager مالک مدل‌های داده، منابع، اعتبارسنجی، کنترل مالکیت و دسترسی به ذخیره‌سازی است. مصرف‌کنندگان باید از API استفاده کنند و نباید مستقیماً به پایگاه داده دسترسی داشته باشند.

## اجرای آزمون‌ها

از ریشهٔ پروژه:

```bash
python3 -m unittest discover -s units/data-manager/tests -v
````
از ریشهٔ پروژه:
```
python3 units/data-manager/run.py
```
آدرس پیش‌فرض محلی: http://127.0.0.1:8080
متغیرهای محیطی اختیاری:
- DATA_MANAGER_DB: مسیر فایل SQLite
- DATA_MANAGER_HOST: آدرس bind؛ پیش‌فرض 127.0.0.1
- DATA_MANAGER_PORT: پورت؛ پیش‌فرض 8080
API هویت را از REMOTE_USER می‌خواند. این مقدار فقط زمانی قابل اعتماد است که یک لایهٔ احراز هویت مورد اعتماد آن را تنظیم کند و کاربران نتوانند آن را مستقیماً جعل کنند.
DATA_MANAGER_ALLOW_INSECURE_HEADER=1 امکان استفاده از X-Manager-ID را برای آزمایش محلی فعال می‌کند. این گزینه برای محیط عملیاتی ناامن است و نباید در آن فعال شود.
راه‌انداز محلی از WSGI استاندارد کتابخانهٔ پایتون استفاده می‌کند و به‌تنهایی TLS، ورود کاربران یا احراز هویت عملیاتی فراهم نمی‌کند. برای استقرار واقعی، اتصال به لایهٔ احراز هویت مورد اعتماد و سرور مناسب الزامی است.
ذخیره‌سازی فعلی مبتنی بر SQLite است. Migrationها به ترتیب اجرا می‌شوند و نسخهٔ Schema همراه هر Migration ثبت می‌شود. پیش از ارتقای پایگاه دادهٔ موجود، نسخهٔ پشتیبان تهیه کنید. Migrationهای مخرب باید برنامهٔ بازیابی مشخص داشته باشند.
- مجوزها بر اساس مالکیت مدل و Resource کنترل می‌شوند؛ سامانهٔ کامل نقش‌ها و مجوزهای قابل‌پیکربندی هنوز وجود ندارد.
- Migrationهای فعلی نسخه‌های تعریف‌شده در کد را پوشش می‌دهند؛ رابط مدیریت و اجرای Migration توسط مدیر هنوز ارائه نشده است.
- قراردادهای contracts/data/ هنوز در وضعیت پیش‌نویس هستند و باید با قراردادهای نهایی CORE تطبیق داده شوند.
