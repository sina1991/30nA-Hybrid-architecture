# استفاده از Demo Trading

## شروع و معامله دستی

۱. وارد `Demo Trading` شوید و حسابی با موجودی اولیه 1000، 3000 یا 5000 USD و یک trade PIN چهاررقمی بسازید. PIN را با Password ورود اشتباه نگیرید.
۲. حساب را انتخاب و تنظیمات Volume/Lots، Leverage، Spread، Commission، Swap و Margin را بررسی کنید. تغییر تنظیمات مالی با سفارش فعال مجاز نیست.
۳. در Manual trade مقادیر SL و TP را وارد کنید. Buy با Ask و Sell با Bid مشاهده‌شده وارد می‌شود؛ قیمت ورود دقیق هنگام ثبت تعیین می‌شود. مثال آموزشی اگر Bid=2000 و Ask=2000.20 باشد: برای Buy می‌توان SL=1995 و TP=2010 داد. این اعداد توصیهٔ معامله نیستند و با قیمت روز باید متناسب باشند.
۴. `Show on chart` خطوط Entry/SL/TP را روی Chart نشان می‌دهد. Positions/History وضعیت، P/L و هزینه‌ها را دارند؛ Close معامله را با قیمت تازه می‌بندد و Cancel سفارش Pending را لغو می‌کند.
۵. ماژول `demo-trade` را در اسلات اضافه کنید. هر اسلات یک معاملهٔ فعال خود را نمایش می‌دهد؛ در Minimize مقدار P/L رنگی دیده می‌شود.

اگر Buy/Sell غیرفعال‌اند، پیام قیمت را بخوانید: آخرین دریافت Collector باید حداکثر ۳۰ ثانیه و زمان کندل حداکثر ۱۲۰ ثانیه قدیمی باشد. تعطیلی بازار، خرابی منبع و ساعت نادرست سرور مانع اجرا هستند. قیمت قدیمی برای ساخت معاملهٔ تازه استفاده نمی‌شود. با دادهٔ تازه کنترل‌ها خودکار فعال می‌شوند.

## ورودی سادهٔ ربات

Market Buy، با مثال قیمت بالا:

```json
{"ACTION":"BUY","sl":1995,"tp":2010,"tradePIN":"0123","request_id":"example-buy-001"}
```

برای Market Sell جای SL/TP باید متناسب با Sell باشد؛ مثلاً در قیمت نزدیک 2000، SL=2010 و TP=1990. ACTION فقط BUY یا SELL است. حجم و اهرم از حساب انتخاب‌شده می‌آیند.

Pending در قیمت مشخص:

```json
{"price":1998,"sl":1990,"tp":2010,"tradePIN":"0123","request_id":"example-pending-001"}
```

با SL < price < TP جهت Buy و با TP < price < SL جهت Sell تشخیص داده می‌شود. نوع Limit/Stop نسبت به قیمت فعلی تعیین می‌شود. با رسیدن قیمت مشاهده‌شده، امکان Fill بررسی می‌شود؛ فاصلهٔ قیمت از bracket یا Margin ناکافی می‌تواند موجب Reject شود. ورود دقیق در قیمت درخواستی هنگام Gap تضمین نمی‌شود.

`account_id` اختیاری است؛ بدون آن حساب فعال استفاده می‌شود. `request_id` برای جلوگیری از ثبت تکراری است: برای یک قصد تازه ID تازه و برای Retry نتیجهٔ نامعلوم همان ID و همان payload را بفرستید. عوض‌کردن محتوا با ID قبلی Conflict است. پنج PIN اشتباه در بازهٔ ۱۵ دقیقه درخواست PIN را موقتاً محدود می‌کند. PIN را در کد ربات، لاگ، قالب اسلات، URL یا Slot Worker ذخیره نکنید.

## Terminal و Worker

ابتدا با CLI وارد حساب شوید؛ دستورها از HTTPS API و Session فایل محافظت‌شده استفاده می‌کنند:

```bash
30na demo state
30na demo bot --input -
30na demo report
```

در دستور دوم JSON بالا را از stdin بدهید؛ PIN واقعی را در آرگومان یا فایل version-controlled قرار ندهید. دستور `30na demo market --input -` ورودی مانند `{"side":"buy","sl":1995,"tp":2010}` می‌پذیرد. CLI برای معامله ID ایجاد می‌کند و Retry خودکار ندارد. اجرای مستقیم `modules/demo-bot/module.py --owner ...` فقط برای اپراتور محلی مورد اعتماد است.

کد دلخواه ربات فقط در CODE/Artifact/Worker/Sandbox اجرا می‌شود. خروجی Worker موفق می‌تواند چنین Intentی باشد:

```json
{"demo_trade":{"ACTION":"BUY","sl":1995,"tp":2010}}
```

PIN نباید داخل خروجی Worker باشد. در فرم Worker نتیجهٔ موفق، execution ID و PIN را جداگانه بدهید؛ Backend مالک اجرا و status=succeeded را بررسی و Intent را با همان حساب اعمال می‌کند. از CLI نیز `30na demo from-worker --input -` با `execution_id` و `tradePIN` در دسترس است. Signal Scripts به‌خودی‌خود معامله باز نمی‌کنند؛ این مرحلهٔ جداگانه لازم است.

## گزارش و حدود مدل

Reports شامل تعداد معاملات بسته، Win rate، Net profit، Commission/Swap، Profit factor، Drawdown، منحنی Equity و گروه‌بندی زمانی/جهت/منبع است. بازهٔ UTC را انتخاب و گزارش را Refresh یا CSV را Download کنید. تاریخچهٔ نمایش محدود و علامت truncation اعلام می‌شود؛ Export بیش از حد پشتیبانی‌شده به‌جای خروجی ناقص خطا می‌دهد.

مدل فعلی USD/XAUUSD و Hedging است. Bid از close مشاهده‌شدهٔ M1 و Ask با Spread شبیه‌سازی‌شده محاسبه می‌شود. SL/TP و Stop-out بر قیمت‌های مشاهده‌شده عمل می‌کنند؛ ترتیب تیک‌های دیده‌نشده بازسازی نمی‌شود. هزینه‌ها و Swap مطابق تنظیمات حساب محاسبه می‌شوند و دقت/شرایط واقعی بروکر MT5 را تضمین نمی‌کنند. واریز، برداشت یا معاملهٔ پول واقعی وجود ندارد. Ledger برای هر owner جدا و خارج از checkout پایدار است.
