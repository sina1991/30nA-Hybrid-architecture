# حساب‌های چندکاربره و Chat — v1.1.0

این قابلیت در نسخه `v1.1.0` منتشر شده است. انتشار GitHub به‌معنای تأیید نصب واقعی روی VPS نیست. برای پذیرش روی VPS، نصب و سناریوهای چندکاربره، قطع سرویس و بازگشت نسخه باید روی یک محیط آزمایشی بررسی شوند.

## راه‌اندازی حساب Admin

۱. مانند قبل با Token حساب نصب‌شده `customer` وارد Dashboard شوید.
۲. در **Account & Settings → User administration**، Username و Password حساب Admin را وارد و **Initialize administrator** را انتخاب کنید. رمز باید حداقل ۱۲ بایت UTF-8 باشد و نباید در مخزن، command history یا Chat قرار گیرد.
۳. در همان بخش، حساب‌های `User` یا `Admin` جدید را بسازید. حساب `customer` و داده‌های موجود آن حفظ می‌شوند؛ ورود قبلی با Token نیز تا زمان غیرفعال‌کردن حساب `customer` معتبر است.
۴. Credentialهای جداگانه هر حساب توسط `30na-account-sync.timer` معمولاً طی کمتر از یک دقیقه ساخته می‌شوند. تا پایان آن، بخش Worker وضعیت در حال آماده‌سازی نشان می‌دهد. بررسی سرویس با `systemctl status 30na-account-sync.timer` و `journalctl -u 30na-account-sync.service` انجام می‌شود؛ مقدار Credential را منتشر نکنید.

غیرفعال‌کردن حساب، Sessionهای آن را فوراً ابطال می‌کند. همگام‌سازی Credentialهای داخلی در نوبت بعدی timer انجام می‌شود؛ اجرای Worker از پیش آغازشده ممکن است تا پایان ادامه یابد. حداقل یک Admin فعال باید باقی بماند. اطلاعات Host Monitor برای کاربران جدید به‌صورت پیش‌فرض مجاز نیست و به تنظیم `THIRTYNA_MONITOR_OWNERS` و دسترسی سیستم‌عامل وابسته است.

## Chat Box

از تب **Slots** گزینه **+ Chat slot** را انتخاب و آن را Pin کنید. اتاق `Public` برای همه حساب‌های فعال است. در بخش **Private chat requests**، کاربر مقابل را انتخاب و درخواست ارسال کنید؛ دریافت‌کننده پس از پذیرش می‌تواند اتاق خصوصی را انتخاب کند. در Slot settings نیز اتاق قابل انتخاب است. پیام‌ها متن هستند و روی سرور ذخیره می‌شوند؛ ارتباط وب از HTTPS استفاده می‌کند اما پیام‌ها End-to-End Encryption ندارند.

[دستورهای Terminal برای حساب و Chat](../development/modules-terminal.md#chat-box-و-حساب-کاربری) در راهنمای Module آمده است. API هویت و Chat به Session معتبر و عضویت در اتاق وابسته است. دسترسی مستقیم به پایگاه‌های محلی از طریق حساب سیستم‌عامل `30na` یک مسیر اپراتوری مورد اعتماد است و جایگزین احراز هویت کاربران وب نیست.

## وضعیت داده و بازگشت

حساب‌ها و Sessionها در `accounts.sqlite3` و پیام‌ها در `chat.sqlite3` زیر `/var/lib/30na/dashboard` نگهداری می‌شوند. Tokenهای Session به‌شکل Hash ذخیره می‌شوند. Credentialهای سرویس در فایل‌های متعلق به Installer و فایل خصوصی حساب سرویس Dashboard قرار دارند؛ از انتشار یا تغییر دستی آن‌ها خودداری کنید.

پیش از ارتقا، نسخه پشتیبان سازگار از state و تنظیمات Installer تهیه کنید. Updater، Unitهای همگام‌سازی مدیریت‌شده را نصب می‌کند؛ بازگردانی Dashboard به نسخه‌ای که این Unitها را نمی‌شناسد نیازمند بررسی و توقف timer جدید و هماهنگی فایل‌های Credential است. بازگشت نسخه معادل حذف ایمن حساب‌ها یا پیام‌ها نیست.

## همگام‌سازی و خطایابی

در صورت نمایش وضعیت آماده‌سازی Worker، ابتدا وضعیت timer و log سرویس را بررسی کنید:

```bash
systemctl status 30na-account-sync.timer
journalctl -u 30na-account-sync.service -n 50 --no-pager
```

Timer هر ۳۰ ثانیه اجرا می‌شود و هنگام فعال‌بودن Installer یا Updater کار را به نوبت بعد موکول می‌کند. فایل `account-upstream.json` خروجی خصوصی Dashboard است؛ `multiuser-secrets.json` و `customer-service-bindings.json` متعلق به root هستند. فایل دوم مسیرهای اصلی حساب `customer` را برای بازیابی پس از فعال‌سازی مجدد حفظ می‌کند. این فایل‌ها حاوی Credential هستند و نباید وارد Git یا خروجی پشتیبانی شوند.

Session تا ۱۲ ساعت معتبر است و Logout آن را باطل می‌کند. محدودیت ورود در حافظه process و بر اساس Username و سقف کلی است؛ حفاظت توزیع‌شده یا MFA نیست. متن Chat حداکثر ۴۰۰۰ کاراکتر، ارسال پیام حداکثر ۶۰ بار در دقیقه برای هر کاربر و درخواست خصوصی معلق حداکثر ۲۰ مورد است.
