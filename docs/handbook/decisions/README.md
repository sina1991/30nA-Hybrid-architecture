# دفتر تصمیم‌های معماری (ADR)

این پوشه مرجع تصمیم‌های معماری است. قراردادها و رفتار واقعی در فایل‌های خودشان تعریف می‌شوند؛ این دفتر چرایی انتخاب‌ها، گزینه‌های بررسی‌شده و پیامدهای تصمیم را نگه می‌دارد.

## وضعیت‌ها

- **Proposed**: پیشنهاد شده، هنوز تأیید نشده.
- **Accepted**: تصمیم پذیرفته شده و مبنای پیاده‌سازی است.
- **Rejected**: بررسی و رد شده؛ علت باید ثبت شود.
- **Superseded**: با تصمیم جدید جایگزین شده؛ به ADR جایگزین پیوند دهید.

## قالب پیشنهادی

```markdown
# ADR-NNN — عنوان

- وضعیت:
- تاریخ:
- تصمیم‌گیرندگان:
- مرتبط با یافته‌ها:
- Commit/شواهد:

## زمینه و مسئله
## گزینه‌ها
## تصمیم
## پیامدهای مثبت و منفی
## امنیت و سازگاری
## برنامه مهاجرت/بازگشت
## تست و معیار پذیرش
## منابع
```

## تصمیم‌های مورد نیاز در این پروژه

1. قرارداد نهایی Worker و مرز Manager/Runtime.
2. چرخه عمر و انتشار Artifact بین CODE MANAGER و WORKER RUNTIME.
3. مدل Sandbox برای اجرای کد غیرقابل اعتماد.
4. نیاز به persistence و scheduler پایدار برای WORKER MANAGER.
5. نسخه‌بندی و سازگاری قراردادهای CORE/DATA/CODE/WORKER.
6. نحوه ارائه APIهای عمومی به Dashboard بدون افشای credential سرویسی.

این فهرست، تصمیم‌های مورد نیاز را ثبت می‌کند؛ به معنی پذیرش هیچ گزینه‌ای نیست.
