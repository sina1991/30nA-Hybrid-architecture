# کتابچه فنی پروژه 30nA Hybrid Architecture

## هدف کتابچه

این کتابچه حافظه فنی ماندگار پروژه است. هدف آن این است که ممیزی، توسعه، عیب‌یابی و بازبینی‌های بعدی از روی شواهد نسخه‌بندی‌شده انجام شوند؛ نه از طریق تکرار بررسی‌های قبلی یا اتکا به گفت‌وگوهای خارج از مخزن.

## روش خواندن

1. ابتدا [خط مبنای ممیزی](00-audit-baseline.md) را بخوانید تا بدانید چه چیزی بررسی شده و چه چیزی هنوز اثبات نشده است.
2. سپس [نمای معماری موجود](../architecture/overview.md) و فصل یونیت مربوطه را مطالعه کنید.
3. برای رفتارهای بین‌یونیتی، فصل‌های قراردادهای CORE و فصل تست‌ها/CI را نیز بخوانید.
4. پیش از هر تغییر، [نقشه راه تکمیل](02-completion-roadmap.md)، [قواعد مستندسازی](01-documentation-governance.md) و دفتر تصمیم‌ها را بررسی کنید.
5. بعد از تغییر، شواهد تست، Commit و هر انحراف از قرارداد را در مستندات ثبت کنید.

## ساختار مستندات

- `docs/architecture/`: معماری کلان، اجزا، جریان داده، وابستگی‌ها و چرخه Worker.
- `docs/migration/`: موجودی و برنامه انتقال منابع/مخازن.
- `docs/standards/`: استانداردهای توسعه و نسخه‌بندی.
- `docs/handbook/`: کتابچه ممیزی و عملیات، فصل‌های یونیت، وضعیت تست و تصمیم‌های معماری.
- `contracts/`: قراردادهای ماشینی/قابل آزمون؛ متن کتابچه جایگزین قرارداد اجرایی نیست.
- `units/*/README.md`: راهنمای نزدیک به کد هر یونیت؛ باید با فصل متناظر کتابچه هماهنگ بماند.

## قانون اعتبار

مستندات باید واقعیت فعلی را از طرح آینده جدا کنند. واژه‌های «پیاده‌سازی شده»، «آزموده شده»، «یکپارچه شده» و «آماده تولید» فقط با شواهد مستقل قابل استفاده‌اند. اگر تست اجرا نشده یا محیط لازم در دسترس نیست، وضعیت باید «تأیید نشده» باشد.
